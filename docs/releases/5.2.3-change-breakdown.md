# 5.2.3 change breakdown

This is an accounting of the initial candidate (then numbered 5.2.2)
`cc420aedb1ef943b18431154e7b7b84e0f120550`, compared with
`origin/main` at `5c8d86b75a3615c654aabc3506322860e8d123a1`. It explains
what was changed; it is not release qualification evidence.

The owner moved this work to **5.2.3**, after the separate 5.2.2 release.
The historical totals below remain bound to the original immutable candidate;
follow-up compatibility, hosted-build, and fixture corrections are outside those totals.

The integrated source checkpoint `806b09d01562d0920a7ec1aef56bf46553ad14fa`
includes the 5.2.2 baseline `c262b05ed67e5936e1cdcbf7206b0922328ba7ea`.
Against that baseline it changes **953 files, +440,619 / -47,067 lines**.
Those exact totals describe that checkpoint, before its artifact-only refresh;
the category table below remains the earlier candidate accounting.

The candidate is a substantial cross-platform feature release with lifecycle
fixes, not a small isolated patch. The approved scope remains ordered
notification collection and durable evidence/recording. This document does
not recommend removing or rescoping that work.

## What the handwritten implementation does

### Ordered notification collection

`GattDatabase.subscribeOrdered` provides one bounded FIFO over selected
characteristics, so order is recorded at the native ingress boundary rather
than reconstructed after independent characteristic callbacks have diverged.
Values carry a source generation and membership/epoch when the host can report
them; unavailable identity remains explicit. The normative contract is
[ordered notification collections](../UNIFIED_SEMANTICS.md#ordered-notification-collections);
the shared TypeScript implementation is in
[`src/core/ordered-*`](../../src/core/), with host transport in the Rust,
Android, Apple, Web, Electron, and Tauri routes.

### Durable recording and recovery

The candidate adds bounded, receipt-backed retention of terminal evidence and
ordered records, plus reclaim/recovery paths when a host/controller is
interrupted. It does not silently claim a complete sequence when the source
cannot establish that fact. The public status and controller model is in
[`src/core/continuation-recording.ts`](../../src/core/continuation-recording.ts),
and the evidence semantics are described in
[the continuation and terminal-evidence sections](../UNIFIED_SEMANTICS.md).

### Explicit ingress loss and lifecycle ownership

The release distinguishes host-global/peer source loss from an exact
per-stream overflow counter. It also fixes concrete ownership races:

- a queued scan callback cannot be attributed to a later scan after a stop or
  restart;
- Android callbacks admitted before an ownership fence remain deliverable,
  while undispatched host work remains cancellable;
- adapter reset preserves the first authoritative terminal reason;
- one lifecycle transition cannot issue duplicate physical CCCD cleanup;
- evidence is staged before delivery so a restart can recover an observed
  terminal instead of treating it as absent.

The contract is [host-global ingress loss](../UNIFIED_SEMANTICS.md#host-global-ingress-loss)
and [peer notification ingress loss](../UNIFIED_SEMANTICS.md#peer-notification-ingress-loss).
These fixes have deterministic and native-synthetic tests; that evidence does
not establish physical-radio qualification.

### Vendored platform work

The `vendor/` changes are platform adapter work in the BlueZ, CoreBluetooth,
and WinRT routes. They are production code, not generated output. The reviewed
notification-ingress and host-specific peripheral changes carry ordered
ingress/lifecycle information to the core so it is not reconstructed after host
callbacks have diverged. This accounting does not assert that every vendored
line is independently necessary.

## Compatibility corrections after the frozen candidate

Review of the candidate against 5.2.1 found source-compatibility breaks. The
corrections below are intentionally additive and preserve all richer runtime
data; they were committed after the initial candidate and are not represented by the
frozen-commit totals above.

| Existing 5.2.1 consumer shape                                                                                                                                   | Candidate break                                                          | Narrow correction                                                                                                                                                                                                                    |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Structural implementations of `GattValueEvent`, `GattDatabase`, `ContinuationRecordingController`, `ExpoBleManager`, `DesktopProcessHost`, and `BleDiagnostics` | New members, including `provenance` and ordered helpers, became required | Keep new members optional on the legacy base interfaces; concrete hosts still implement them. A caller that explicitly needs an unavailable new capability gets the established `capability.unsupported` result rather than a crash. |
| Exhaustive consumers of `ContinuationBacklogStreamEnd.reason`                                                                                                   | The legacy three-reason union was widened with `source-failed`           | Restore the legacy public union. Richer source-failure records stay on versioned recovery/evidence paths, which already retain the original native record instead of relabeling it.                                                  |
| Consumers assigning `ContinuationRecordingStatus.runtimeFailure` or `collectionFailure` to their 5.2.1 types                                                    | Durable/persisted diagnostic state widened those fields                  | Preserve the exact legacy fields and add optional `runtimeDiagnostic` / `collectionDiagnostic` siblings for durable, oversized, and extended diagnostics.                                                                            |
| Backend-SDK consumers supplying `PlatformErrorDetail.metadata` in the established serializable-record shape                                                     | The public metadata type was narrowed to a portable-record variant       | Restore `SerializableRecord` at the public boundary. Existing snapshot normalization still accepts wire `Uint8Array` input and owns it internally.                                                                                   |

The API reports are regenerated with the compatibility corrections at the
final freeze. None of the descriptions above claim that qualification,
hosted CI, or publication has occurred.

## Follow-up corrections

The additional release review restored legacy TypeScript source compatibility,
completed omitted Apple build-source selections and Windows compile wiring,
and corrected failures in the strict Rust and packed-consumer gates. The Apple
spool migration tests exposed an SQL token concatenation and a schema comparison
that rejected SQLite's owned rename formatting. The declared version-8 route
also selected the wrong historical acknowledgement shape. These corrections
retain the legacy rows and constraints; the spool's earlier candidate formats
are separate from the published 5.2.1 primary journal format.

Hosted Windows tests exposed a recovery-storage provisioning failure: the exact
file and directory handles requested generic read/write access before trying to
set their owner and DACL. They now also request `WRITE_DAC` and `WRITE_OWNER`;
the current-user owner, protected single-owner DACL, and no-reparse validation
remain unchanged. This uses the caller's existing Windows permissions without
requesting elevation. The native regression follows the configured root,
dedicated recovery directory, and sidecar, then verifies null-DACL rejection.
Both installation and verification use `FILE_ALL_ACCESS`, the concrete
full-control mask Windows stores for file objects.

The completed Windows run also reproduced existing SQLite files losing access
when directory protection propagated replacement ACLs to their children.
Only directory provisioning now opens its held handle with `MAXIMUM_ALLOWED`,
which [suppresses that propagation](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-setsecurityinfo).
Directory validation and sidecar opens retain their existing explicit rights;
the strict owner, single ACE, protected DACL, and reparse checks remain unchanged.
The native Windows regression preserves and rewrites an ordinary file created
before directory protection, while the original Tauri test reopens and
acknowledges an existing SQLite recording.

The same review traced a separate public Windows recording failure: native
continuation configuration installed no trusted storage protector, but ordinary
durable attachment queried its v2 recovery sidecar before any scan. That shared
configuration method now uses the existing current-user Windows protector,
matching the offline Node-API and Tauri trusted-host paths. Original continuation
and mobile tests retain the public configuration route rather than injecting
a replacement registry that would bypass this regression.

Final Windows package qualification found that installing that protector on
every public configuration call broke repeated same-directory setup. The
Node/Electron controller configures its directory whenever `recordings()` is
requested, so this affected ordinary repeated recording. The shared trusted
Windows setup now serializes first installation and repeated validation under
the existing registry lock, retaining the installed protector and directory
identity. Native continuation, standalone Node-API readers, and Tauri use the
same route. Different directories and explicit protector replacement still
fail. The mobile fixture no longer configures the protector before testing the
public setup method. Original Electron and public GATT cleanup assertions stay
unchanged; no deletion retry or optional cleanup workaround was added.

Windows package tests also found that a successfully closed Node-API host kept
SQLite handles open while JavaScript retained its wrapper. The existing close
path now releases terminal-ledger ownership shared with the native scan
observer and evicts only its directory's idle journal handles. Persisted rows
remain on disk, and live owners, outstanding diagnostics, and unpersisted
failure evidence retain their existing ownership. Recovery tests reopen the
saved records after shutdown; no additional dispose call is required.
Independently opened recording readers now expose optional `releaseIdle()` for
their cached handles, using that same idle-only primitive. The controller stays
usable and reopens saved journals lazily; its legacy structural type and native
store interface retain compatibility through optional members.

The extra PR review reproduced a Web notification lost when disconnect arrived
before the terminal-evidence fence drained. Admission checks and byte ownership
now occur when the callback arrives. The queued delivery preserves that admitted
prefix through lifecycle teardown; explicit owner removal still discards an
unread callback. Public regressions cover both outcomes.

A later review reproduced unvalidated persisted Web quota counts entering
arithmetic, including string concatenation during reservation. One private
guard now validates the version, key, positive safe-integer capacity, and
nonnegative safe-integer count before all three quota arithmetic paths.
Malformed state aborts without deleting evidence or changing quota; the
three-route regression checks retry after repair. No storage schema or public
type changes are needed.

Real Chrome 157 also reproduced recovery scans failing before reading any rows:
the IndexedDB `getAll` count exceeded its unsigned 32-bit range. Both scans now
use a valid count. Releasing a recreated runtime reservation could also delete
an already staged or committed row. Release now checks persisted state and
preserves that evidence and its quota for retry and recovery acknowledgement.
The [browser fixture](../../__tests__/web/web-terminal-evidence-browser-fixture.js)
and [retained browser receipt](5.2.3-browser-proof.json) cover listing,
reattachment, runtime release, staged retry, exact bytes, and acknowledgement.
The receipt records the failing baseline, passing outcomes, and source/bundle
hashes. This is actual IndexedDB, Web Locks, and Web Crypto execution evidence;
it does not provide Bluetooth-radio qualification.

Actual iOS and packed tvOS consumer builds exposed Objective-C calls to Swift
throwing methods without their generated error selectors. Completion bridges
now call the existing Swift methods and serialize refusals with the same
`failureJson` path as the rest of the module. This preserves the original Swift
entrypoints and JavaScript method shapes, including structured error fields.
The ordered-recording start-status and retirement selectors also now use the
`handle:` label required by the current New Architecture codegen contract.

Test-fixture corrections create private directories for the private recovery
store, initialize its lazy sidecar through the journal before fault injection,
configure Windows v2 fixtures with the trusted native storage protector, and
supply the producer failure required by staged recovery. They retain the
negative permission, atomicity, receipt identity, and legacy-data assertions.
Tauri fixtures whose dispatcher intentionally lives until process exit now use
the existing child-process fixture boundary before the parent removes SQLite
files. Recovery fixtures release their explicit leases, and the standalone
restart proof uses the current producer, lease, and reservation payloads.
The completed Windows Rust run additionally exposed invalid fixture names
from `SystemTime` debug formatting and cleanup while test-held SQLite handles
were live. Portable fixture identifiers, explicit owner drops, existing idle
release, and the existing process fixture fence correct those test failures.
The behavioral assertions and unsupported-storage negative cases are retained.
Sidecar fixtures explicitly drop their spool, ledger, and registry handles
before the existing idle-cache cleanup removes their directories. A failed
append that intentionally retains a process-owned diagnostic uses the existing
child-process fixture fence instead. The null-DACL rejection test opens its
corruption handle through the production exact-sidecar helper, preserving both
the successful corruption assertion and the validator's permission refusal.
Native canonical-byte fixtures use a raw synthetic central as the sole terminal
queue consumer. Their former provider-backed setup also ran a destructive event
pump, which could consume the terminal before the test read it. Provider
transport coverage keeps its existing setup; native byte, digest, recovery, and
UTF-16 assertions remain intact.
The final Rust runs also reproduced scan cleanup and recovery defects: late scan
start compensation attempted to retire an already fenced callback epoch, and
legacy receipt retirement recreated missing proof. The corrections retain the
required compensating physical stop and refuse missing retirement proof without
recreating it. Independent review checked failed-stop retry and receipt ownership.
A proposed mobile unsubscribe reorder did not reproduce a production defect;
it was removed. The existing empty-prefix and accepted-prefix cancellation
scenarios remain covered without changing that production path.

The additional public-flow review found that early OS-ended scan terminals
could expose a restart before the shared core finished callback cleanup. The
next start now joins that terminal-owned stop flight under its own budget and
cancellation, preserving the public restart behavior without bypassing the old
callback fence. The public tests retain immediate restart after the terminal;
consumers do not need a private native ownership barrier.

The supervisor now retains the original cleanup failure when recovery stops.
Previously it replaced that failure with a generic `connection.failed`; a
successful final cleanup could then erase the underlying diagnostic. The
correction preserves the actual error code and platform detail using the same
mapping as the supervisor's other cleanup paths. Retry and ordering rules are
unchanged. A regression covers one failed release followed by successful final
cleanup, keeping that first failure visible in the stopped snapshot.

The stale-marker fixture waits for the original database's Services Changed
event before discovering a replacement graph. It retains the original peer
identifier and proof that a stale marker is not written. Cleanup test failures
also retain the native error as their cause instead of reporting only a refused
outcome.

The extra independent reviews examined public compatibility, durable ownership,
and these migration/build corrections. Executed qualification is recorded in
the release pull request against its exact candidate; static review alone is
not a passing release gate.

## Interpretation

The candidate has clear, intentional ownership: ordered ingress plus durable
evidence must cross every supported host boundary, so a real implementation
touches shared code, native cores, generated bindings, transports, tests, and
artifacts together. It is still large. Passing focused tests does not prove
that every line is necessary or that no regression exists; release qualification
must assess the exact post-compatibility commit.
