# UBM 5.0 packaging slice (PACKAGING card, U8 vehicle)

Lane-scoped candidate work for `trackourhealth/bun-mono#1188`. This document is
the U8 packaging record: what ships, what stays dev-only, how license inclusion
survives packing, what the SBOM covers, and what a 4.x developer must change
for 5.0.

**5.0.0-rc prerelease lane (F01).** The U8 "never by a version bump" ruling
is superseded: package version reads `5.0.0-rc.0` and the packed tarball is a
real prerelease artifact with an explicit native distribution strategy (Rust
sources ship; packed consumers build dispatch addons from them and verify
package/core/fingerprint identity at runtime). Still no final `5.x` shipment
claim, no tags, no publish, no merge to `main`, no push past the
license/provenance hold. `contracts/**` stays frozen (read-only).

## 1. Export map: per-surface ship/dev-only decisions

No new `package.json` export subpath is added by this slice. The map keeps its
25 shipped subpaths plus `./package.json` (26 keys), exactly as pinned by
`CheckHostExports`, `CiRelease.canonicalPackage`, `Package.identity`, and
`PackageSurface4`. Any added subpath would break those four suites and the
`llms.txt` entrypoint coverage enforced by `pnpm docs:check` — that is
intentional: a new public surface must arrive with its own contract, tests,
and docs, not ride along with packaging.

## 2. License-file + NOTICE + contribution-terms inclusion

U-LICENSE is adopted-local (SAL byte-exact, contribution terms verbatim modulo
wrapping; legal/provenance review pending, pushes held). Inclusion survives
packing on both layers:

- npm tarball: `package.json` `files` already lists
  `LICENSE-UBM-SOURCE-AVAILABLE-1.0.md`, `NOTICE`,
  `UBM-CONTRIBUTION-TERMS-1.0.md`, the top-level `LICENSE` (the UBM text) and
  the retained Apache text at `LICENSES/Apache-2.0.txt`;
  `verify-package-tarballs.js` allowlists all five and the consumer proof
  asserts they install. No change needed; verified, not assumed.
- Rust crates: all seven new 5.0 crates now carry `publish = false` (never
  publishable to crates.io), `license-file = "../../LICENSE-UBM-SOURCE-AVAILABLE-1.0.md"`,
  and the canonical `repository`. The four `bindings/*` crates additionally
  dropped their inaccurate `license = "MIT"` shortform (new 5.0 material is
  SAL, matching the `native/tauri` precedent asserted by
  `License.packaging.test.js`).

| Crate                                                               | Before                                                | After                                                 |
| ------------------------------------------------------------------- | ----------------------------------------------------- | ----------------------------------------------------- |
| `crates/ubm-core`                                                   | license-file + repository, no `publish`               | + `publish = false`                                   |
| `crates/ubm-desktop`                                                | license-file + repository, no `publish`               | + `publish = false`                                   |
| `crates/ubm-fake-radio`                                             | license-file + repository, no `publish`               | + `publish = false`                                   |
| `bindings/napi`, `bindings/wasm`, `bindings/jni`, `bindings/uniffi` | `license = "MIT"`, no publish/license-file/repository | SAL `license-file` + `publish = false` + `repository` |

`cargo metadata --offline` confirms all seven resolve with `publish: []`
(cargo's form of `publish = false`), no SPDX `license`, and the SAL
`license_file`. Only `publish`/`license`/`repository` fields were touched;
`edition`, `rust-version`, dependencies, and targets are unchanged, and the
pinned toolchain (`rust-toolchain.toml`, 1.98.1) is untouched.

## 3. SBOM / THIRD_PARTY_LICENSES and the new Rust deps

`pnpm release:artifacts:check` is green with no drift: the committed
`SBOM.cdx.json` + `THIRD_PARTY_LICENSES.json` still match the frozen npm
production graph. Per `docs/DEPENDENCY_AND_ARTIFACT_POLICY.md` those
inventories describe **JavaScript** production/optional runtime dependencies;
this slice adds no npm dependency, so regeneration is correctly a no-op.

The new Rust dependency graph is **not** merged into the SBOM by this slice,
deliberately: the SBOM generator (`scripts/release/`) sits outside this
slice's exclusive paths, and inventing license-review overrides for 166
external crates to force a merge would fabricate review evidence. The
authoritative Rust inventory below comes from the real Rust generator
(`cargo metadata --offline`, 173 nodes: 7 workspace + 166 external,
`Cargo.lock` pinned). Merging it into the CycloneDX/THIRD_PARTY artifacts is
recorded as open U8 item 1 — required before any release containing 5.0 Rust material, since the policy
states any future vendored binary/source dependency must enter the generator
before release.

## 5. Migration notes: 4.x → 5.0 developer impact

**What stays.** All 26 export subpaths keep their shape; `package.json`
version reads `5.0.0-rc.0` (F01 prerelease lane); the bob `commonjs` +
`module` + `typescript` build,
the `ubm` CLI, the Expo plugin passthrough, and the `dbus-next`/`expo`/
`react`/`react-native` optional-peer model are unchanged. The Apache
text is retained at `LICENSES/Apache-2.0.txt` for inherited 4.x material; the
top-level `LICENSE` is the UBM license. No application code changes
are required by this slice.

**What moves (prerelease lane).** The 5.0 kernel (`crates/ubm-core`) and
desktop central (`crates/ubm-desktop`) ship as sources and execute real
operations: the N-API `UbmCentral` dispatch (built from packed sources,
direct-path load, no new npm surface), the Tauri plugin (frozen core
identities + bootstrap revision admission), the RN shared-core seam, and
the 5.x podspec Rust-core selection. The TCK rust-driver stays dev-only.
Downstream Rust consumers take the crates by path dependency, never from
crates.io (`publish = false`).

**License change pointer.** New 5.0 material is under the source-available
terms, not the Apache license: read
[`../LICENSE-UBM-SOURCE-AVAILABLE-1.0.md`](../LICENSE-UBM-SOURCE-AVAILABLE-1.0.md),
[`../NOTICE`](../NOTICE), and
[`../UBM-CONTRIBUTION-TERMS-1.0.md`](../UBM-CONTRIBUTION-TERMS-1.0.md); new
contributions require the explicit assent recorded in
[`../CONTRIBUTING.md`](../CONTRIBUTING.md). Publication stays on hold pending
legal/provenance review regardless of CI state.

## 6. Open U8 items

1. Merge the Cargo-resolved Rust graph into `SBOM.cdx.json` /
   `THIRD_PARTY_LICENSES.json` via the real generator (scripts/release/ is
   outside this slice) — required before any release containing 5.0 Rust material per the artifact policy.
2. Revisit the `./tck/rust-driver` dev-only verdict once a real Rust backend
   ships with prebuild distribution (an export that always fails closed in
   consumers would be a broken promise today).
3. N-API dispatch distribution stays build-from-shipped-sources (F01):
   no `.node` prebuild matrix is declared for the dispatch addon — a
   future prebuild matrix (ABI/arch, signing) must arrive with its own
   strategy; echo stand-ins must never become the shipped binary.
4. `example/android` eager-`applicationContext` crash loop stays main-line
   triage, not a lane fix (per gate ledger).
5. Tauri dispatcher authority migration (drive op scheduling through
   `ubm-desktop`; the dispatcher keeps radio ownership), the RN
   binding-backed backend projection (blocked on the JNI/UniFFI op
   surface, echo-only today), and tvOS Rust coverage stay open follow-ups.
6. Physical-radio load evidence (BLE controller, Apple device/simulator
   load, Windows) runs on device/matrix CI; Linux proofs compile and
   drive the synthetic radio only.
