# UBM 5.0 packaging (current release behavior and U8 record)

Lane-scoped candidate work for `trackourhealth/bun-mono#1188`. This document
describes what ships, what stays dev-only, how license inclusion survives
packing, what the SBOM covers, and what a 4.x developer must change for 5.0.

## Current release behavior

`5.0.0-rc.4` is a prerelease, not a final `5.x` stability claim.
[`../RELEASE.md`](../RELEASE.md) governs its tag procedure: the initial RC
publication is allowed only from an annotated `v5.0.0-rc.4` tag on the exact
current `main` commit. GitHub Actions publishes it through npm trusted
publishing with provenance under the `next` dist-tag. The npm registry and
GitHub Release, rather than this document, establish publication status.

The release tarball has an explicit native distribution strategy:

- CI builds, verifies, and packs the complete maintained Node-API prebuild
  matrix. The desktop-core loader selects only its exact platform/architecture
  binary, verifies its identity sidecar and source identity before a radio
  operation, and never builds Rust in an installed consumer. The retained
  CoreBluetooth and WinRT prebuilds are also packed while their legacy private
  boundaries remain in the package.
- CI builds the iOS RustCore XCFramework from the tagged sources, verifies its
  slice/hash/source-identity chain, and stages it in `ios/RustCore` before
  packing. The release verifies the committed Android native prebuilts against
  those same tagged sources.
- Rust sources remain in the tarball for source integrations such as the Tauri
  plugin. They are not an npm export and are not the desktop runtime fallback.

The evidence in the U8 sections below records the earlier F01
build-from-shipped-sources design and its receipts where it says so. It is
historical evidence, not a description of the release tarball's current
desktop-consumer behavior. `contracts/**` stays frozen (read-only).

## 1. Export map: per-surface ship/dev-only decisions

No new `package.json` export subpath is added by this slice. The map keeps its
25 shipped subpaths plus `./package.json` (26 keys), exactly as pinned by
`CheckHostExports`, `CiRelease.canonicalPackage`, `Package.identity`, and
`PackageSurface4`. Any added subpath would break those four suites and the
`llms.txt` entrypoint coverage enforced by `pnpm docs:check` — that is
intentional: a new public surface must arrive with its own contract, tests,
and docs, not ride along with packaging.

| Surface                                                          | Verdict                                                                                                                                | Justification                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `contracts/**` (C-UBM.0.1.2-DRAFT text)                          | Dev-only, never exported                                                                                                               | Frozen dev-time authority, not runtime. Runtime reads compiled artifacts; the contract text ships in `src/` for Codegen/type builds but resolves through no subpath.                                                                                                                                                                                                                                                                           |
| N-API dispatch (`bindings/napi` `UbmCentral` over `ubm-desktop`) | Internal runtime prebuilds ship; sources stay unexported                                                                              | The release tarball packs the maintained `native/desktop-core/prebuilds/<platform>-<arch>/` binaries and identity sidecars. `native/desktop-core/index.js` loads only the matching prebuild and fails closed on a missing, malformed, or mismatched artifact; it does not compile Rust for an installed consumer. There is no `./napi` subpath. |
| WASM artifacts (`bindings/wasm`)                                 | Dev-only, never exported                                                                                                               | Same echo-stand-in status. The web host contract stays `unified-ble-manager/web`, not a wasm echo module.                                                                                                                                                                                                                                                                                                                                      |
| JNI/UniFFI scaffolds (`bindings/jni`, `bindings/uniffi`)         | Dev-only, never exported                                                                                                               | FFI-NATIVE feasibility scaffolds for Android/JVM hosts, not BLE backends. | Test-only fault hooks (`src/tck/test-only-fault-hooks.ts`)       | Bytes ship inside `lib/`+`src/` like all compiled sources; never resolvable via any subpath (asserted `ERR_PACKAGE_PATH_NOT_EXPORTED`) | Only `__tests__` imports them (via source). The TCK packaging proof (`scripts/ci/check-tck-test-only-packaging.js`) now also covers the built `./testing` entry and `src/testing.ts` — the entry most likely to absorb the hooks by accident — closure, runtime exports, and source.                                                                                                                                                           |

Enforcement (all in `scripts/ci/`, all fail-closed):

- `check-napi-artifact-packaging.js`: sections A (crate metadata) + B
  (export-map guard + exact-`5.0.0-rc.N` version claim) run offline via
  `pnpm test:pack-napi-proof`; section C verifies the packed source trees,
  fingerprint seal, no stray `.node`, and every desktop-core prebuild/sidecar.
  The release invocation requires all six desktop-core targets. Section D
  verifies the installed consumer's dev-only export boundary and shipped
  materials.
- `f01-packed-dispatch-proof.js` is retained as a historical F01
  source-build proof. It packs the candidate, installs it clean, builds the
  dispatch addon from packed sources, drives
  scan/connect/discover/read/write/subscribe/timeout/dispose in Rust, verifies
  package/core/fingerprint identity, compiles the Tauri plugin + Apple matrix
  from packed sources, and asserts the Android prebuilts and podspec lane.
  It does not replace the release prebuild, clean-tarball, or Electron
  acceptance gates.
- `check-tck-test-only-packaging.js` (extended): built `index`,
  `backend-sdk`, **and `testing`** entries plus their sources.
- `pack-install-smoke.js` (additive hooks): tarball proof after
  `verify-package-tarballs` in both modes, consumer proof after the ESM
  asserts in the full mode.

## 2. Historical U8 license-file + NOTICE + contribution-terms receipt

At the cited U8 snapshot, U-LICENSE was adopted-local (SAL byte-exact,
contribution terms verbatim modulo wrapping). This receipt records how
inclusion survived packing on both layers; consult `RELEASE.md` for the live
release decision:

- npm tarball: `package.json` `files` already lists
  `LICENSE-UBM-SOURCE-AVAILABLE-1.0.md`, `NOTICE`,
  `UBM-CONTRIBUTION-TERMS-1.0.md`, the top-level `LICENSE` (the UBM text) and
  the retained Apache text at `LICENSES/Apache-2.0.txt`;
  `verify-package-tarballs.js` allowlists all five and the consumer proof
  asserts they install. No change needed; verified, not assumed.
- Rust crates: all seven new 5.0 crates now carry `publish = false` (never
  publishable to crates.io), `license-file = "../../LICENSE-UBM-SOURCE-AVAILABLE-1.0.md"`,
  and the canonical `repository`. The four `bindings/*` crates additionally
  dropped their inaccurate `license = "MIT"` shortform (new 5.0 material is
  SAL, matching the `native/tauri` precedent asserted by
  `License.packaging.test.js`).

| Crate                                                               | Before                                                | After                                                 |
| ------------------------------------------------------------------- | ----------------------------------------------------- | ----------------------------------------------------- |
| `crates/ubm-core`                                                   | license-file + repository, no `publish`               | + `publish = false`                                   |
| `crates/ubm-desktop`                                                | license-file + repository, no `publish`               | + `publish = false`                                   |
| `crates/ubm-fake-radio`                                             | license-file + repository, no `publish`               | + `publish = false`                                   |
| `bindings/napi`, `bindings/wasm`, `bindings/jni`, `bindings/uniffi` | `license = "MIT"`, no publish/license-file/repository | SAL `license-file` + `publish = false` + `repository` |

`cargo metadata --offline` confirms all seven resolve with `publish: []`
(cargo's form of `publish = false`), no SPDX `license`, and the SAL
`license_file`. Only `publish`/`license`/`repository` fields were touched;
`edition`, `rust-version`, dependencies, and targets are unchanged, and the
pinned toolchain (`rust-toolchain.toml`, 1.98.1) is untouched.

## 3. Historical U8 SBOM / THIRD_PARTY_LICENSES receipt

At the cited U8 snapshot, `pnpm release:artifacts:check` was green with no
drift: the committed
`SBOM.cdx.json` + `THIRD_PARTY_LICENSES.json` still match the frozen npm
production graph. Per `docs/DEPENDENCY_AND_ARTIFACT_POLICY.md` those
inventories describe **JavaScript** production/optional runtime dependencies;
this slice adds no npm dependency, so regeneration is correctly a no-op.

The new Rust dependency graph is **not** merged into the SBOM by this slice,
deliberately: the SBOM generator (`scripts/release/`) sits outside this

states any future vendored binary/source dependency must enter the generator

## 5. Migration notes: 4.x → 5.0 developer impact

**What stays.** All 26 export subpaths keep their shape; `package.json`
version reads `5.0.0-rc.4` (F01 prerelease lane); the bob `commonjs` +
`module` + `typescript` build,
the `ubm` CLI, the Expo plugin passthrough, and the `dbus-next`/`expo`/
`react`/`react-native` optional-peer model are unchanged. The Apache
text is retained at `LICENSES/Apache-2.0.txt` for inherited 4.x material; the
top-level `LICENSE` is the UBM license. No application code changes
are required by this slice.

**What moves (prerelease lane).** The 5.0 kernel (`crates/ubm-core`) and
desktop central (`crates/ubm-desktop`) execute real operations. The npm
release provides the verified, exact-platform N-API desktop-core prebuild;
the N-API source remains an internal direct-path implementation detail with no
new npm surface. The Tauri plugin consumes the retained Rust sources (frozen
core identities + bootstrap revision admission); the RN shared-core seam and
the 5.x podspec RustCore selection also ship. The TCK rust-driver stays
dev-only. Downstream Rust consumers take the crates by path dependency, never
from crates.io (`publish = false`).

**License change pointer.** New 5.0 material is under the source-available
terms, not the Apache license: read
[`../LICENSE-UBM-SOURCE-AVAILABLE-1.0.md`](../LICENSE-UBM-SOURCE-AVAILABLE-1.0.md),
[`../NOTICE`](../NOTICE), and
[`../UBM-CONTRIBUTION-TERMS-1.0.md`](../UBM-CONTRIBUTION-TERMS-1.0.md); new
contributions require the explicit assent recorded in
[`../CONTRIBUTING.md`](../CONTRIBUTING.md). The release gate and publication
procedure are defined in [`../RELEASE.md`](../RELEASE.md); this document does
not independently declare a publication hold or release decision.

## 6. Packaging follow-ups

1. Merge the Cargo-resolved Rust graph into `SBOM.cdx.json` /
   `THIRD_PARTY_LICENSES.json` via the real generator (scripts/release/ is
   outside this slice) — required before any release containing 5.0 Rust material per the artifact policy.
2. Revisit the `./tck/rust-driver` dev-only verdict once a real Rust backend
   ships with prebuild distribution (an export that always fails closed in
   consumers would be a broken promise today).
3. Keep the complete native prebuild matrix, `native/PREBUILDS.json`, every
   desktop-core identity sidecar, and the release tarball in one verified
   chain. A new target or loader behavior requires its own matrix, identity,
   clean-tarball, and Electron acceptance proof; echo stand-ins must never
   become the shipped binary.
4. `example/android` eager-`applicationContext` crash loop stays main-line
   triage, not a lane fix (per gate ledger).
5. Tauri dispatcher authority migration (drive op scheduling through
   `ubm-desktop`; the dispatcher keeps radio ownership), the RN
   binding-backed backend projection (blocked on the JNI/UniFFI op
   surface, echo-only today), and tvOS Rust coverage stay open follow-ups.
6. Physical-radio load evidence (BLE controller, Apple device/simulator
   load, Windows) runs on device/matrix CI; Linux proofs compile and
   drive the synthetic radio only.
