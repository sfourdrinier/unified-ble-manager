# UBM 5.0 packaging slice (PACKAGING card, U8 vehicle)

Lane-scoped candidate work for `trackourhealth/bun-mono#1188`. This document is
the U8 packaging record: what ships, what stays dev-only, how license inclusion
survives packing, what the SBOM covers, and what a 4.x developer must change
for 5.0.

**Not a release.** Package version stays `4.0.28` on this lane by orchestrator
ruling: the 5.0 candidate is identified by branch+SHA
(`codex/ubm5-packaging`), never by a version bump — bumping now would mislabel
every packed tarball. No tags, no publish, no merge to `main`, no push past the
license/provenance hold. `contracts/**` is frozen (read-only; no discrepancy
found in this slice's scope). `crates/**`, `bindings/**`, `src/**`,
`native/**` are read-only except the `publish`/`license`/`repository` metadata
fields this slice was explicitly allowed to set.

## 1. Export map: per-surface ship/dev-only decisions

No new `package.json` export subpath is added by this slice. The map keeps its
25 shipped subpaths plus `./package.json` (26 keys), exactly as pinned by
`CheckHostExports`, `CiRelease.canonicalPackage`, `Package.identity`, and
`PackageSurface4`. Any added subpath would break those four suites and the
`llms.txt` entrypoint coverage enforced by `pnpm docs:check` — that is
intentional: a new public surface must arrive with its own contract, tests,
and docs, not ride along with packaging.

| Surface | Verdict | Justification |
|---|---|---|
| `contracts/**` (C-UBM.0.1.2-DRAFT text) | Dev-only, never exported | Frozen dev-time authority, not runtime. Runtime reads compiled artifacts; the contract text ships in `src/` for Codegen/type builds but resolves through no subpath. |
| N-API artifacts (`bindings/napi` `.node` echo) | Dev-only, never exported | Echo-only feasibility stand-in — its own manifest says "NOT BLE functionality". Platform/ABI-specific binaries cannot ride the portable tarball; release prebuilds remain the only `.node` path and this lane produces none. |
| WASM artifacts (`bindings/wasm`) | Dev-only, never exported | Same echo-stand-in status. The web host contract stays `unified-ble-manager/web`, not a wasm echo module. |
| JNI/UniFFI scaffolds (`bindings/jni`, `bindings/uniffi`) | Dev-only, never exported | FFI-NATIVE feasibility scaffolds for Android/JVM hosts, not BLE backends. No Java/Kotlin/Swift consumer compiles against them from npm. |
| `ubm-desktop` consumers | Dev-only at the npm layer | Rust crate consumed via cargo (path dependency), not via npm subpaths. The npm desktop surface stays `./node/*` + `./electron/main`. Its npm-tarball absence is asserted, not assumed. |
| TCK rust-driver (`src/tck/rust-driver`) | Dev-only, never exported | Parity driver that requires the unpacked real `.node` build, absent from every packed consumer; test infrastructure per the "deterministic backends are never production fallbacks" invariant. Its bytes already ship inside `lib/`+`src/` like all compiled sources, but no subpath resolves to it (`ERR_PACKAGE_PATH_NOT_EXPORTED`, asserted in the consumer proof). Revisit only when a real Rust backend ships with prebuild distribution. |
| Test-only fault hooks (`src/tck/test-only-fault-hooks.ts`) | Bytes ship inside `lib/`+`src/` like all compiled sources; never resolvable via any subpath (asserted `ERR_PACKAGE_PATH_NOT_EXPORTED`) | Only `__tests__` imports them (via source). The TCK packaging proof (`scripts/ci/check-tck-test-only-packaging.js`) now also covers the built `./testing` entry and `src/testing.ts` — the entry most likely to absorb the hooks by accident — closure, runtime exports, and source. |

Enforcement (all in `scripts/ci/`, all fail-closed):

- `check-napi-artifact-packaging.js` (new): sections A (crate metadata) + B
  (export-map guard + no-5.0-version-claim) run offline via
  `pnpm test:pack-napi-proof`; sections C (tarball) + D (installed consumer)
  run inside `pack-install-smoke.js`.
- `check-tck-test-only-packaging.js` (extended): built `index`,
  `backend-sdk`, **and `testing`** entries plus their sources.
- `pack-install-smoke.js` (additive hooks): tarball proof after
  `verify-package-tarballs` in both modes, consumer proof after the ESM
  asserts in the full mode.

## 2. License-file + NOTICE + contribution-terms inclusion

U-LICENSE is adopted-local (SAL byte-exact, contribution terms verbatim modulo
wrapping; legal/provenance review pending, pushes held). Inclusion survives
packing on both layers:

- npm tarball: `package.json` `files` already lists
  `LICENSE-UBM-SOURCE-AVAILABLE-1.0.md`, `NOTICE`,
  `UBM-CONTRIBUTION-TERMS-1.0.md` alongside the retained Apache `LICENSE`;
  `verify-package-tarballs.js` allowlists all four and the consumer proof
  asserts all four install. No change needed; verified, not assumed.
- Rust crates: all six new 5.0 crates now carry `publish = false` (never
  publishable to crates.io), `license-file = "../../LICENSE-UBM-SOURCE-AVAILABLE-1.0.md"`,
  and the canonical `repository`. The four `bindings/*` crates additionally
  dropped their inaccurate `license = "MIT"` shortform (new 5.0 material is
  SAL, matching the `native/tauri` precedent asserted by
  `License.packaging.test.js`).

| Crate | Before | After |
|---|---|---|
| `crates/ubm-core` | license-file + repository, no `publish` | + `publish = false` |
| `crates/ubm-desktop` | license-file + repository, no `publish` | + `publish = false` |
| `bindings/napi`, `bindings/wasm`, `bindings/jni`, `bindings/uniffi` | `license = "MIT"`, no publish/license-file/repository | SAL `license-file` + `publish = false` + `repository` |

`cargo metadata --offline` confirms all six resolve with `publish: []`
(cargo's form of `publish = false`), no SPDX `license`, and the SAL
`license_file`. Only `publish`/`license`/`repository` fields were touched;
`edition`, `rust-version`, dependencies, and targets are unchanged, and the
pinned toolchain (`rust-toolchain.toml`, 1.98.1) is untouched.

## 3. SBOM / THIRD_PARTY_LICENSES and the new Rust deps

`pnpm release:artifacts:check` is green with no drift: the committed
`SBOM.cdx.json` + `THIRD_PARTY_LICENSES.json` still match the frozen npm
production graph. Per `docs/DEPENDENCY_AND_ARTIFACT_POLICY.md` those
inventories describe **JavaScript** production/optional runtime dependencies;
this slice adds no npm dependency, so regeneration is correctly a no-op.

The new Rust dependency graph is **not** merged into the SBOM by this slice,
deliberately: the SBOM generator (`scripts/release/`) sits outside this
slice's exclusive paths, and inventing license-review overrides for 166
external crates to force a merge would fabricate review evidence. The
authoritative Rust inventory below comes from the real Rust generator
(`cargo metadata --offline`, 172 nodes: 6 workspace + 166 external,
`Cargo.lock` pinned). Merging it into the CycloneDX/THIRD_PARTY artifacts is
recorded as open U8 item 1 — required before any release containing 5.0 Rust material, since the policy
states any future vendored binary/source dependency must enter the generator
before release.

## 5. Migration notes: 4.x → 5.0 developer impact

**What stays.** All 26 export subpaths keep their shape; `package.json`
version reads `4.0.28`; the bob `commonjs` + `module` + `typescript` build,
the `ubm` CLI, the Expo plugin passthrough, and the `dbus-next`/`expo`/
`react`/`react-native` optional-peer model are unchanged. The Apache
`LICENSE` is retained for inherited 4.x material. No application code changes
are required by this slice.

**What moves (lane only, unreleased).** The 5.0 kernel (`crates/ubm-core`),
desktop central (`crates/ubm-desktop`), FFI feasibility bindings, and the TCK
rust-driver exist on the lane but expose **no new npm surface**: Node/desktop
consumers keep using `./node/*` and `./electron/main`, backend authors keep
using `./backend-sdk` + `./testing`, and the TCK runner stays
`runBackendTck`. Downstream Rust consumers (if any) take the crates by path
dependency, never from crates.io (`publish = false`).

**License change pointer.** New 5.0 material is under the source-available
terms, not the Apache license: read
[`../LICENSE-UBM-SOURCE-AVAILABLE-1.0.md`](../LICENSE-UBM-SOURCE-AVAILABLE-1.0.md),
[`../NOTICE`](../NOTICE), and
[`../UBM-CONTRIBUTION-TERMS-1.0.md`](../UBM-CONTRIBUTION-TERMS-1.0.md); new
contributions require the explicit assent recorded in
[`../CONTRIBUTING.md`](../CONTRIBUTING.md). Publication stays on hold pending
legal/provenance review regardless of CI state.

   triage, not a lane fix (per gate ledger).
5. Physical-radio / Apple / Windows evidence rows remain open (no BLE
   controller on the Linux host); pack smokes prove package shape only.
