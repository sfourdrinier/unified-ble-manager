## Status and closure rules

- **Open / confirmed:** current source confirms the stated defect or constraint;
  no fix has been made here.
- **Open / reported:** supplied review identifies work; implementation scope or
  platform behavior still needs verification. Not automatically a proven bug.
- **Open / acceptance:** a required future check, not evidence of a present bug.
- **Closed baseline:** already corrected; retain the regression and evidence.

Each UBM item requires an implementation/decision link, focused failing-to-passing
regression where applicable, documentation delta, and correctly labelled evidence
before closure. Record exact source and artifact identities. Compilation,
simulator launch, synthetic radio, and physical radio are different evidence.
No item is closed merely because a bot is unavailable, a workflow was cancelled,
an omitted lane did not fail, or npm accepted publication.
