# ADR: Stable application boundary for 4.0 (PR1)

**Status:** Accepted design baseline
**Date:** 2026-08-20
**Supersedes:** RC1 provisional application surface; establishes PR1–PR4 pre-stable reset window

## Decision

PR1 deliberately breaks RC1 provisional names to create the stable five-minute application surface. The core reliability substrate (ownership, generations, bounded streams, cancellation, TCK, protocol negotiation, diagnostics) is preserved inside and wrapped by a focused façade.

- The root `unified-ble-manager` becomes application-only. It exports `BleManager`, `BleAdapter`, `BlePeer`, `PeerReference`, `BleConnection`, `GattDatabase`/`GattService`/`GattCharacteristic`/`GattDescriptor`, `GattSubscription`, `BleCapabilities`, `BleError`, `OperationOptions`, `StreamPreset`, cleanup records, and helpers. It does not export `attachBleBackend`, provider construction, branded `Deadline`/`Capacity`/`AttachmentId`, raw paths, or generic attachment parameters. Those move to `/advanced` or `/backend-sdk`.

- Public application types are non-generic. The implementation wraps generic core resources in internal adapters without losing static safety. `BleManager`, `BleConnection`, `GattCharacteristic` and others have no type parameters at the application boundary.

- One public name per resource: `BleManager`, `BlePeer`, `PeerReference`, `BleConnection`, `GattDatabase`, `GattService`, `GattCharacteristic`, `GattDescriptor`, `GattSubscription`, `BleError`. No `Ipc*`/`Tauri*`/`Local*` public variants; host-specific classes remain internal.

- Application operation options are `{ signal?: AbortSignal, timeoutMs?: number }`. Timeouts normalize once to a monotonic `Deadline`. `timeoutMs` must be a finite positive safe integer; zero/negative/NaN/Infinity/ non-finite reject with `argument.invalid`. Nested helpers preserve the earliest deadline and compose `AbortSignal` without losing cause.

- Stream configuration uses presets `latest`/`balanced`/`lossless-bounded`/`custom` mapping to exact bounded capacities. `custom` requires explicit budgets via `/advanced`. Defaults are `balanced` for scan/notification and `lossless-bounded` for indications.

- Identity is split: ephemeral runtime identity (manager/operation/attachment nonces) may be cryptographically random per-attachment and is never a restoration key; restoration-bound identity is deterministic across relaunch, derived by the trusted native host from a versioned domain separator `unified-ble-manager:restoration:v1` plus the normalized application identifier, one restoration ID, and optional generation. No wall-clock, package version, or per-launch randomness participates. JavaScript receives the opaque derived identifier from the host and never forges it. `BleManagerCreateOptions` is `{ instanceId?: string, adapterId?: string, diagnostics?: DiagnosticsOptions, restoration?: { applicationId, restorationId, generation? } }`. `instanceId` does not alter restoration.

- Host factories are zero-plumbing: `createReactNativeBleManager(options?: BleManagerCreateOptions)`, `createExpoBleManager`, `createWebBleManager`, `createTauriBleManager`, and `createBluezBleManager`/`createCoreBluetoothBleManager`/`createWinRtBleManager` take only `BleManagerCreateOptions` (plus host-specific optional fields like `adapterId`). Tests use `*WithEnvironment` injection. Tauri normal factory imports `invoke`/`Channel` from `@tauri-apps/api/core` internally; Web returns one `BleManager` (chooser is a capability); RN no longer asks for `clientId`/`managerId`/`hostSessionScope` or a caller-supplied clock/control.

- No compatibility aliases for RC1 names. The RC1→RC2 migration table is the compatibility mechanism.

- Entrypoints after PR1: `unified-ble-manager` (app), `/react-native`, `/expo`, `/web`, `/node/bluez`, `/node/corebluetooth`, `/node/winrt`, `/electron/main`, `/electron/renderer`, `/tauri`, `/advanced`, `/backend-sdk`, `/testing`, `/codecs`, `/profiles/*`. No wildcard deep imports.

- The façade contains no policy state beyond option normalization and one internal generation-bound handle. All lifecycle, ownership, and generation decisions remain in `src/core`/`src/manager`.

## Consequences and gates

- PRs 5–12 are additive against the RC2 freeze. After PR4 no portable runtime breaking change without a documented release-blocking defect.
- Package surface is enforced by committed API extractor reports under `etc/api/*.api.md` and export allowlists in `__tests__/PackageSurface4.test.js`. Drift fails CI unless intentionally reviewed.
- Restoration derivation is covered by golden fixtures at `__tests__/fixtures/restoration-identity.golden.json` and shared with native configuration code (Swift/Kotlin/Rust) that reimplements the same domain-separated SHA-256 derivation.
- `pnpm validate:evidence`, `pnpm test:package`, `pnpm lint`, `pnpm prepack`, and `node scripts/ci/pack-install-smoke.js` remain the required local gates before push. `publish.yml` remains tag-driven via npm trusted publishing/OIDC (`v4.0.0-rc.*` → `latest`).

## Rejected alternatives

- Retaining RC1 generic manager types at the root and adding overloads for the new surface: rejected because it would permanently burden application code with backend identity parameters and require compatibility aliases immediately after stable.
- Keeping manual `clientId`/`managerId`/`hostSessionScope` bookkeeping in application factories: rejected because it creates restoration and ownership desynchronization bugs; hosts already know the application identifier.
- Adding a second `scan.peers({ retentionMs })` helper alongside `duplicates: 'coalesced'`: rejected per Revision 4 review—application current-view is `duplicates: 'coalesced'` only; PR9 may add a derived lost-peer timeout on that same view.
- Freezing `ScanClause.peers` in PR4 as a dormant placeholder: rejected—PR4 freezes without `peers`; PR5 adds it additively under frozen Boolean rules.
- Publishing a full canary for every ordinary PR head: rejected—canaries are required only at RC checkpoints or when package shape, native ABI/protocol, native prebuilds, plugin schema, or npm/Cargo coordination changes.
