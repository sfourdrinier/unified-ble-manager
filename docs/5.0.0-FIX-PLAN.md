## Orchestrator decisions (recorded; owner is informed and may overrule)
1. **PR210-24:** remove the post-timeout `is_connected` probe (AGENTS.md: "a result reads the operation's own answer"). A timed-out disconnect stays `operation.timed-out` with retained `Disconnecting` ownership; the later OS release surfaces as a lifecycle `Released` event and a retry returns already-released. Split `peer.list` failures from `PeerNotFound`.
2. **Liveness backstops** (apply only when the caller gives no budget): `LIVENESS_OP` 120 s, `LIVENESS_CLEANUP` 10 s, `LIVENESS_SCAN_START` 30 s, compensation 1 s. Caller budgets travel as relative `budgetMs`.
3. **Delivery mode (corrected by PARITY-INVENTORY.md):** each host keeps at least its legacy semantics and gains honesty. Android: honor the requested CCCD mode (legacy did). Tauri: restore 4.x's `require-notification` property check. CoreBluetooth (Node + iOS): legacy TS property check for `require-*` is preserved; delivery reported `unknown`. WinRT: legacy chose notify-then-indicate; Rust path must keep notify preference (btleplug prefers indicate → Windows OS adapter writes the CCCD itself) and may now honor `require-*`. BlueZ: legacy ignored mode; Rust path applies the property check (no app that worked before breaks: a requirement is only rejected where the characteristic lacks the property). Never report `indication:false` as fact.
4. **Mobile radio ownership — parity:** everything the legacy RN route supports must work on the Rust route before deletion of anything legacy: state restoration (iOS `CBCentralManager` restoration, Android background/foreground-service leases), multiple concurrent managers sharing the platform radio, background operation, bonding/pairing, MTU/PHY/priority requests, `listAdapters`. MOBILE-RUST must design the owner as a process-owned radio with per-session leases (not one radio per session) if that is what restoration and multi-manager require; the per-session-radio shortcut in spec-mobile.md is REJECTED where it loses any of these.
5. **Contract:** `NotificationValue.indication: boolean` → `delivery: 'notification'|'indication'|'unknown'` in the backend contract (5.0 is a major; CHANGELOG entry).
6. **NAPI distribution:** ship verified per-platform prebuilt Rust NAPI addons; no cwd / cross-platform fallbacks.
7. **NO capability regressions (owner directive 2026-09-17).** Every capability the legacy CoreBluetooth/WinRT/BlueZ backends report today (pairing/bonding/security state/unpair, adapter selection, MTU request/effective MTU/max write length, connected RSSI, adapter power/authorization, connection priority/PHY where supported, etc.) MUST work on the Rust path before that platform's default flips. Gaps are filled by narrow OS adapters inside `ubm-desktop` (Windows: `windows` crate WinRT APIs; macOS: CoreBluetooth via objc2) behind `RadioBoundary`, with btleplug for the common path — packet DESKTOP-PARITY. A parity test asserts the Rust backend reports and exercises every capability the legacy backend reports. Windows flip is gated on parity + physical proof on a Windows host.
8. **PR210-23 ADR status:** owner decision; not edited without the owner's quote.
9. **Correction to review:** PR210-06's claim that the Tauri TS side never sends `operation.cancel` is wrong — the shared IPC client does (`src/ipc/client.ts`, `src/electron/renderer.ts:195-200`); the cancel is lost on the Rust side. Rust also sets `retryable` on every aborted/timed-out error (`btleplug_dispatcher.rs:219-222`) — part of PR210-22.

10. **btleplug patching allowed:** where parity needs native objects btleplug owns (macOS `maximumWriteValueLength`/`canSendWriteWithoutResponse`, btleplug macOS `mtu()` stuck at 23, Windows CCCD mode/`MaintainConnection`, BlueZ `mtu().unwrap()` panic), vendor a minimally patched btleplug under `vendor/btleplug` via `[patch.crates-io]`, each patch documented + tested, license/SBOM regenerated. Prefer narrow OS adapters that don't need the patch when feasible.
11. **Parity source of truth:** `PARITY-INVENTORY.md` (per-host tables). Every row with a gap is a required fix owned by a packet below. **False-claim registrations** (capability registered but every call fails) are fixed first: the capability must actually work (preferred) — deregistering is allowed only where the legacy route also did not support it.
12. **(REVISED by owner override)** The legacy iOS reference path restored earlier is a TEST REFERENCE ONLY until Phase 4; `legacyTypeScriptCore` (both platforms) and every other legacy opt-in are REMOVED in Phase 4 along with the legacy code. The Apple/Android first-party TCK legs must be re-admitted against the Rust route (RN-PROVIDER).
13. **Defaults (REVISED):** all public factories use the Rust core now (Node macOS/Windows/Linux, Electron main, RN/Expo Android/iOS, Tauri). Parity gaps are FAILING blocker tests, never skipped; nothing ships until all are green. No legacy opt-in exists in public API.
