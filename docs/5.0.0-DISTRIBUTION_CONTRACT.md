# UBM 5.0 distribution contract (D2 work package i)

**Status:** Draft — normative for D2 packages (ii)–(v) once accepted.
**Authority:** ADR `docs/ADR/2026-09-5.0-pr210-review-cutover-scope.md`, D2
(CI-built prebuilts, explicit source mode). This document turns the ADR's ten
normative points into file paths, mode selection, identity fields, and
verification gates. Anything marked TBD is pinned by the cutover or by the
owning work package; nothing TBD may silently default.

## 1. One package, two modes

There is exactly one npm package (`unified-ble-manager`). Native Rust
artifacts travel inside it (whole `ios/` and `android/` trees are already in
`package.json` `files[]`). Tarball size is measured before any split/CDN
design is considered (package iv).

Build mode is EXPLICIT configuration — never inferred from `.git`, installed
toolchains, or host sniffing (PR210-19):

| `UBM_NATIVE_BUILD` | Mode | Meaning |
|---|---|---|
| unset or empty | `prebuilt` (default) | Consume the CI-verified artifacts in the package. Missing, corrupt, or identity-mismatched artifacts are an ACTIONABLE error before any BLE/session work. Never a silent source build, never a legacy fallback. Rust, the NDK and Node are never invoked. |
| `prebuilt` | `prebuilt` | Same, stated explicitly. |
| `source` | `source` | Build from the shipped `crates/` + `bindings/` sources with the canonical builders (same scripts CI uses). Stale outputs are rejected, not silently reused. |
| anything else | — | Hard error: `pod install` raises `Pod::Informative`, Gradle configuration throws `GradleException`. Values are compared exactly (no trimming, no case folding). |

The knob is one variable, parsed identically by `unified-ble-manager.podspec`
and `android/build.gradle`.

Source preparation is a direct, repo-owned command — never a CocoaPods or
Gradle side effect a consumer layout can skip:

| Command | Runs | When |
|---|---|---|
| `pnpm native:apple:prepare` | `sh ios/build-rust-core.sh` | Before `pod install`, whenever the Rust sources change. For a `:path` consumer: `UBM_NATIVE_BUILD=source pnpm --dir <ubm checkout> native:apple:prepare`. |
| `pnpm native:android:prepare` | `sh android/build-rust-cdylib.sh --prepare` | Optional: Gradle source mode builds each profile itself; this pre-builds every ABI into the same staging (`android/build/ubmRustCdylib/<profile>/<abi>`) and proves the toolchain. |

## 2. Apple artifacts (expanded by package ii)

- **Shipped artifact:** `ios/RustCore/RustCore.xcframework` (static linkage stays).
- **Declared slices** (exact, proven by `xcodebuild -create-xcframework` on
  Xcode 26.6; `LibraryIdentifier | platform | variant | architectures`):
  `ios-arm64 | ios | — | arm64`,
  `ios-arm64_x86_64-simulator | ios | simulator | arm64,x86_64`,
  `tvos-arm64 | tvos | — | arm64`,
  `tvos-arm64-simulator | tvos | simulator | arm64`. The table lives in
  `ios/verify-rust-core.sh` and `APPLE_DECLARED_LIBRARIES` in
  `scripts/release/native-build-identity.js` (a test keeps them equal). One
  binary name across all slices (`libubm5_uniffi_echo.a` until the cutover
  renames the core — CocoaPods rejects mixed names).
- **Staging identity:** `ios/RustCore/build-identity.json`
  (`ubm-apple-rustcore-identity/1`, written by the builder): sealed
  `sourceDigest` + `bindingSchema`, `contractRevision`, profile, toolchain,
  Xcode, the Info.plist sha256, and every slice parsed from Info.plist with
  `plutil` (identifier, platform, variant, architectures, LibraryPath,
  sha256, bytes).
- **Consumption:** through the EXISTING pod integration
  (`s.vendored_frameworks`). No `prepare_command` in any mode (CocoaPods
  never runs it for `:path` pods, ADR D2.7). The "Verify staged RustCore"
  script phase runs `ios/verify-rust-core.sh` before any source compiles in
  both modes: exact declared slice set parsed from Info.plist, Info.plist
  sha256 and every slice sha256/size, no undeclared archive. In `source`
  mode it also runs `native-build-identity.js --check-apple`, which rejects
  a staging whose sealed digests no longer match the sources and prints the
  `native:apple:prepare` command.
- **Source mode:** the explicit preparation step
  (`pnpm native:apple:prepare`) runs `ios/build-rust-core.sh` (the canonical
  builder, also used by CI artifact production) BEFORE pod install. The
  script fails loudly outside macOS+Xcode and without Node, and verifies the
  staging it wrote.
- **Source-compiled in consumer:** Swift adapters, generated UniFFI Swift
  (`bindings/uniffi/generated/swift/ubm_echo.swift`), RN native integration.
  Only the Rust static slices are prebuilt.
- **Signing:** DECIDED (package iv, closes T3-signing): no signing step.
  The framework ships static archives (`.a` slices) consumed via a
  path-based podspec; static libraries carry no code signature and need
  none — signing happens once, by the app developer, over their final app
  bundle. A signing step would be theater: there is no dynamic framework
  to sign and no signature a consumer could verify. If distribution ever
  moves to a binary/dynamic vehicle, that migration reopens this clause
  deliberately.

## 3. Android artifacts (expanded by package iii)

- **Shipped artifacts:** `android/src/main/jniLibs/<ABI>/libubm5_jni_echo.so`
  (standard location; no duplicate packaging paths). Current ABI set:
  `arm64-v8a`, `x86_64` — any change (e.g. adding `armeabi-v7a`) is a
  deliberate contract revision, not drift.
- **Consumption:** through the EXISTING Gradle library. No separate Maven
  publication required for the npm/RN/Expo path.
- **Committed identity:** `android/src/main/jniLibs/build-identity.json`
  (`ubm-android-jnilibs-identity/1`, written by
  `android/refresh-prebuilt-jniLibs.sh`): sealed `sourceDigest` +
  `bindingSchema`, `contractRevision`, profile, toolchain, NDK, and per ABI
  the target triple, file, sha256 and bytes. Gradle's prebuilt path checks
  the hash chain; the publish gate
  (`native-build-identity.js --check-android-prebuilts`) additionally fails
  when the sealed digests differ from the tagged sources (or are `null`,
  i.e. the prebuilts predate identity sealing), so every Rust change
  requires a maintainer refresh before release.
- **Source mode:** canonical builder `android/build-rust-cdylib.sh`, selected
  only by `UBM_NATIVE_BUILD=source` (the `.git` inference is removed). The
  Gradle input graph comes from `native-build-identity.js --inputs jni`, not
  a hand-maintained list. The host-aware NDK linker path makes macOS and
  Linux contributor flows both real. Outputs are isolated by ABI/profile.
- **Source-compiled in consumer:** Kotlin adapters, generated JNI glue,
  RN-specific native integration. Only the Rust `.so` files are prebuilt.
- **Page size:** shipped libraries MUST pass a real 16 KB page-size
  compatibility check (package iii verification gate).

## 4. Identity and fingerprint (extended seal, no new manifest zoo)

`scripts/release/generate-build-fingerprint.js` is extended (not replaced) so
the seal binds, per platform:

- `package`: name@version that produced the build (skew fails).
- `contractRevision`: C-UBM revision from `crates/ubm-core/src/contracts.rs`.
- `sourceDigest` (per binding: `napi`, `jni`, `uniffi`): sha256 over the
  sorted `relpath\0sha256(content)\n` lines of the binding crate and its
  transitive path dependencies (parsed from `Cargo.toml`
  `[dependencies]`/`[build-dependencies]`, their target-specific and
  workspace-inherited forms; never dev-dependencies) — each contributing
  `Cargo.toml`, its build script and `src/**` — plus the workspace
  `Cargo.toml`, `Cargo.lock`, `rust-toolchain.toml` and
  `bindings/ubm_build_identity.rs`.
- `bindingSchema` (per binding, closes T1): the same digest over the
  wrapper-side declarations that must match the binary — napi
  `bindings/napi/src/{dispatch,lib}.rs`; uniffi the UDL plus the generated
  Swift (`ubm_echo.swift`, `ubm_echoFFI.h`, `ubm_echoFFI.modulemap`); jni
  `bindings/jni/src/lib.rs` plus every Java class named by an exported
  `Java_*` symbol (the shipped `android/src/main/java` copy and the
  `bindings/jni/java` owner copy).
- `features`: enabled feature set of the Rust build.
- `targets`: per-artifact target triple / arch / platform slice.
- `deploymentMinimum`: iOS/tvOS deployment target, Android minSdk (values TBD
  by packages ii/iii from the podspec/gradle declarations).
- `toolchain`: compiler + SDK identity (pinned Rust toolchain, Xcode/NDK
  versions from the CI producers).
- `artifacts`: per-file sha256 + bytes for every shipped native binary
  (`native.apple` slices join the existing `native.android` map).
- `fingerprint`: sha256 over the canonical seal (tamper-evident).

One implementation computes `sourceDigest` and `bindingSchema`:
`scripts/release/native-build-identity.js` (Node built-ins only; shipped in
the package so packed source mode works). It regenerates
`src/generated/native-build-identity.ts` (`--write`; `prepack` runs
`--check` and fails on drift) and prints the digests for the builders
(`--print-env <binding>`), which pass them to cargo as
`UBM_BUILD_SOURCE_DIGEST` / `UBM_BUILD_BINDING_SCHEMA`. Each binding's
`build.rs` includes `bindings/ubm_build_identity.rs`, which embeds them
(`"unsealed"` when unset — always rejected at runtime; a malformed value
fails the build) and writes `$OUT_DIR/ubm_build_identity.rs` with the
`UBM_BUILD_*` constants and `ubm_build_identity_json(contract_revision)`,
the frozen `ubm-native-build-identity/1` record:
`{ schema, binding, contractRevision, sourceDigest, bindingSchema, target,
profile, features, rustc }`.

"Built from" MUST be proven (source/dependency digest bound to artifact
hashes), not just "present together". Native bootstrap identity is verified
before sessions/BLE start. Fail-closed on ANY drift: changed bytes, added or
removed files, substituted binaries, or a tampered seal. Mtimes are never
consulted.

## 5. Verification pipeline (package iv wires it into CI/release)

Declared inputs → canonical build → bindings + identity → verification →
packed candidate → clean consumer acceptance. Gates:

1. Canonical builders produce the artifacts from authoritative source.
2. Slice/ABI set matches §2–§3 exactly (no extras, no missing).
3. 16 KB page-size check passes on every shipped `.so`.
4. Extended seal verifies; tarball checks cover the new native paths.
5. Clean-consumer acceptance WITHOUT Rust installed (bare RN + Expo: build
   and invoke the core).
6. Contributor source-build acceptance (`UBM_NATIVE_BUILD=source`, edit a
   Rust fn, rebuild, prove the changed identity loads).
7. Negative artifact tests: removed, substituted, corrupted, and mismatched
   artifacts each fail clearly pre-BLE.
8. Lifecycle ownership: multiple clients, recreation, background/foreground,
   teardown — one native owner, no competing radio owners.

## 6. JS integration (unchanged)

`unified-ble-manager/react-native` and `unified-ble-manager/expo` remain two
entrypoints into ONE native implementation. No Expo Modules API rewrite, no
second BLE runtime. The native host owns the authoritative Rust runtime; RN
and Expo attach clients (package v proves both entrypoints against the
production binding).
