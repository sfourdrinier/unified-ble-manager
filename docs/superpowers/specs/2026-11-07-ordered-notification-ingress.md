# Connection-scoped ordered notification ingress

## Goal and meaning

Provide an ordered, loss-reporting collection of notifications across selected characteristic instances on every supported UBM backend. This is the order in which a defined connection-owned host ingress accepts events; it is not a claim about radio transmission order, values the operating system never delivered, or completeness of a device's history. Do not synthesize or infer ordering from timestamps or independently scheduled characteristic streams.

## Consumer contract

A collection is opened on one current connection/database generation with a nonempty, immutable set of distinct characteristic instances and their requested delivery modes. It exposes one bounded ordered stream and an explicit asynchronous close. A value carries the collection and connection generation, member identity, owned bytes, delivery kind, and a strictly increasing, losslessly transported ingress ordinal. The ordinal is assigned once before per-characteristic fan-out or staging and is not regenerated in JavaScript. Existing individual subscriptions continue to work and must retain their own ownership of physical notification registrations.

The intended public entry point is `GattDatabase.subscribeOrdered(members, options)`, with full characteristic handles rather than UUID-only identities. Each member receives a stable collection-local ID. Transport the ordinal as a canonical decimal unsigned 64-bit string and terminate explicitly if its native counter is exhausted; do not pass it through the existing per-subscription numeric sequence mapper. The ordered stream has explicit value, loss and terminal records. Loss records distinguish known member, group and unknown scope, and allow unknown item or byte counts; native broadcast lag counts skipped broadcast records, not necessarily lost values. The close result is authoritative for cleanup because a terminal may precede asynchronous cleanup.

Existing per-subscription streams need a separate host-global source-loss control: a count of dropped host records is not an exact loss count for each candidate stream, and unknown bytes must not be reported as zero. Keep the existing attributable overflow counters exact. A global notice shared with several candidate streams describes possible impact and must not be summed as if each stream independently lost that many values. Error-policy consumers must see the uncertainty before conservative termination.

The collection reports loss, source failure, database change, disconnect, explicit closure, and cleanup outcomes without representing an uncertain tail as complete. Value admission and invalidation share an owner linearization: values admitted before its fence drain in order, while callbacks after that fence are rejected. A platform-queued or radio tail remains unknown when the platform cannot prove it was delivered before the fence. A per-characteristic consumer cannot infer loss from gaps in global ordinals, because other members may account for those ordinals. A bounded queue reserves a terminal path: if it cannot preserve accepted values and control events, it terminates with explicit loss rather than silently dropping a marker. When the native source cannot attribute a loss to one member, the collection reports an unknown affected count or scope rather than inventing precision.

Install the group route and its bounded staging before the first CCCD enable. Sequential setup buffers ingress events until all members are acquired. A value is admitted only when its bytes and an ordered slot have been reserved. Deliver every admitted value or explicitly report loss or an uncertain tail if it cannot be delivered; preserve raw bytes for values retained by the consumer. A failed or aborted setup returns a normalized primary error, each member's acquisition or indeterminate state, bounded setup observations or explicit loss/uncertainty when they cannot be returned, and per-member/group cleanup outcomes. Retain failed cleanup ownership for retry, including an enable that succeeds after timeout or cancellation. Never disable a physical subscription owned by another consumer. Teardown and service change fence the exact generation, account for admitted events and uncertain tails, and cannot deliver old-generation callbacks into a new collection. Reconnect requires a new collection. An ordered collection alone never authorizes an application-level history acknowledgement.

Register, retire and re-register of a member are serialized with value admission by the actual source owner. Retire acknowledges only after an ordered fence enters a reliable bounded FIFO; old admitted values precede that fence, and subsequent admitted values use the new logical epoch. Do not permanently reject re-registration within a connection or infer a callback's earlier physical subscription from its UUID. Native callbacks already queued before the owner sees them have an uncertain platform tail; a physical enable token alone does not identify a logical owner while another subscriber keeps the CCCD enabled. If a fence or source control is lost, fail the collection explicitly instead of routing through an unproven boundary.

## Boundaries and work

- **Android:** `OwnedAndroidGattRadio.kt` must serialize callback admission, subscription staging and activation under a connection-generation owner before any per-characteristic staging. The current split `isActive`/`stage` check can lose an activation-racing callback, and staging overflow is not conveyed by its list-only activation result. Route ordinals, values and loss through `OwnedRadioPort.kt`, the mobile host/wire, and the React Native provider.
- **Apple mobile:** establish the same owner at CoreBluetooth delegate ingress in `ios/Owned/OwnedCoreBluetoothProtocolRadio.swift` and its cancellation/notification classification path, preserving the callback decision through the Swift adapter and mobile host/wire.
- **Desktop:** replace separately scheduled per-characteristic forwarding with a single connection-owned receive/demultiplex path in `crates/ubm-desktop/src/btleplug_backend.rs`, before `central.rs` routes to per-instance hubs. Extend the maintained vendored btleplug source with an additive event-bearing stream that reports peer-wide lag separately, including lag immediately followed by closure; preserve retained controls and the existing value-only API. Carry source loss and closure through the desktop boundary without assigning an unattributed source gap to a particular characteristic. On BlueZ, define the ingress at the serialized merged native source unless the upstream merge is changed and qualified; on WinRT serialize concurrent callbacks at the publishing boundary. CoreBluetooth, WinRT and BlueZ must each be implemented and tested.
- **Web:** serialize accepted DOM notifications at a connection-owned ingress before characteristic stream fan-out. The resulting order is callback-ingress order, not peripheral transmission order.
- **Boundaries and consumers:** add a group operation and ordered event types to the public and backend GATT contracts. Implement all supported direct TypeScript backends as well as native React Native, Node N-API, Electron IPC, Tauri and Web; do not substitute unsupported stubs. Version and negotiate the mobile, native and IPC transport contracts before CCCD changes, and carry values and terminal controls without recreating ordinals. Keep existing subscribers compatible. Update Expo and Bun WHOOP consumers to select the ordered collection for multi-characteristic capture.
- **Recording:** the current per-route pump/journal append order is not original ingress order. Durable ordered capture must admit the same group FIFO and retain ordinals, loss controls and generation across restart. Do not describe the existing journal as ordered acquisition.

## Verification and status

Implementation has started in the vendored desktop source; the collection is not yet available. For every backend and actual public transport, use deterministic interleaved A/B callbacks, callbacks during CCCD setup, independent existing subscribers, partial enable/abort, bounded overflow, unattributable source loss, disconnect/service change/reconnect, duplicate UUID instances, stale callbacks and transport closure. Round-trip decimal ordinals beyond JavaScript's safe integer range and at the unsigned 64-bit boundary; test exhaustion and malformed wire values. Android additionally needs a deterministic activation-versus-callback regression and staging-overflow regression. Check loss controls and clean ownership on every exit, and test durable replay and crash/ack boundaries when durable group capture is implemented. Native synthetic tests, native builds, and physical-radio experiments are distinct evidence levels. Device-specific complete-history and ACK behavior require separate protocol evidence and physical testing.
