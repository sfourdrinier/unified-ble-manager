# Plan: R01 RN factory flip to the production Rust core binding

**Finding:** PR210 R01 (BLOCKER) — "RN does not default to Rust, and its
injected route still constructs the TS lifecycle core."
**Repair (handoff, verbatim scope):** wire a production-generated native
session binding into the ordinary 5.x factory; route the public API to
native-owned operations without constructing the old scheduling/lifecycle
core; reject a missing or incompatible required Rust binding before any BLE
effect; retain legacy only as a clearly isolated test/reference or
separately authorized legacy API.
**Acceptance (handoff):** from a packed, clean native consumer, call the
ordinary public factory without a `rustCore` test option; poison
`UnifiedBleCore.attach` and legacy provider entry points; create, scan,
connect, discover, read/write, subscribe, cancel, destroy reach the real
native binding; missing/mismatched core rejects and releases host resources.
**Decision input:** D1 full cutover (a); D3(a) native session facade (done:
producer branch merged as 8569fc7b, RUSTCORE 11/11).

## Ground truth (read 2026-09-17, lane 8569fc7b)

- `src/react-native-app-manager.ts` (83 lines): `createReactNativeBleManager`
  passes `rustCore` through only when the caller injects one; the no-options
  factory builds on the TS protocol providers (`providerFor` →
  `createBleManagerFromProvider` → `BleManager.create` →
  `UnifiedBleCore.attach` at `src/manager/ble-manager.ts:229`).
- `src/react-native-manager.ts` (190 lines): env factory selects
  `createRustCoreManager` only when `options.rustCore !== undefined`; that
  route still ends in `createBleManagerFromProvider` (attach). Both R01
  complaints confirmed in code.
- `src/backends/reactnative/react-native-rust-core-provider.ts` (2182
  lines): `ReactNativeRustCoreBackend implements BleCentralBackend` already
  dispatches the full verb set to native ops (`session.dispose`,
  `peers.connected`, `scan.start/stop/take`, `connection.connect`,
  `connection.disconnect`, `gatt.discover/read/write/read-descriptor/
  write-descriptor/subscribe/unsubscribe`, `adapter.state`,
  `counters.describe`). Self-contained (own session, streams, counters,
  destroy); takes only `now` + restoration coordinator — no core services.
- Native op surface today (Kotlin `RustCoreSessionRouter`, Swift
  equivalent): `central.status`, `echo.*`, `kernel.*`, `ble.transition`,
  `staged.*`, `scan.*`. `connection.*` / `gatt.*` / `peers.*` /
  `session.dispose` hit `capability.unsupported` (router default). ubm-core
  exposes no connect/gatt/subscribe ops (R02-Apple production-radio scope).
- `src/expo.ts` (959 lines) already composes over
  `createReactNativeBleManager` / `...WithEnvironment` — the flip propagates
  (one native owner preserved); Phase C is verification, not new code.
- `createPublicBleManager` consumes `InternalBleManager` (the
  `manager/ble-manager.ts` class shape, ~25 members). A native-owned manager
  must satisfy that shape without `UnifiedBleCore`.

## Explicit blocker (honesty record)

Full R01 acceptance (all 8 verbs through the REAL native binding) is
impossible until the core exposes connect/gatt/subscribe over JNI/UniFFI +
router tables (the tracked "connect/subscribe core follow-up", R02-Apple /
R03 scope: real radio authority in the core). This plan lands the flip —
factory default, native-owned manager, rejection, poison acceptance, device
proof for the available surface — with `connection.*` / `gatt.*` verbs
structurally routed and failing closed (`capability.unsupported` minted by
the native router, never TS fallback) until the core grows them. The flip
must not be marked complete against connect/subscribe until that follow-up
lands and the 8-verb matrix reruns.
