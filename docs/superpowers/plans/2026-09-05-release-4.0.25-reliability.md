# 4.0.25 Reliability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the 18 verified 4.0.23 reliability findings (BLE-01..BLE-18) on `release/4.0.25` without claiming hardware qualification.

**Architecture:** Keep logical state and native ownership together across every terminal path. Public settlement, native completion, and cleanup receipt stay distinct. Generation/lease checks happen after every await that mutates ownership. Do not disable replay protection, inflate every buffer, swallow cleanup errors, or report cancellation acknowledgement as physical completion.

**Tech Stack:** TypeScript (core/public/backends), Rust (Tauri dispatcher), Swift (iOS owned radio), Kotlin (Android GATT radio), Objective-C++ (Electron CoreBluetooth), Jest, Cargo tests, Android unit tests.

**Source review:** `docs/review/2026-09-05-4.0.23-reliability-review.md`
**Verification:** `docs/review/2026-09-05-4.0.23-reliability-review-verification.md` (17 confirmed, BLE-17 partial)

**Branch:** `release/4.0.25` from `c6a3984e` (package 4.0.23). Another engineer owns 4.0.24; do not touch that worktree.

**Global constraints for every task:**
- TDD: failing regression first, watch it fail, then minimal production change.
- Do not bump `package.json` version or edit `CHANGELOG.md` / README version strings. The orchestrator does that after merge.
- Do not disable replay checks, raise all limits, or swallow `.ok()` / empty catch.
- Preserve first-party and third-party backend contracts, per-client ownership, bounded memory, binary copy semantics, generation checks.

### Task 1: Tauri ownership and admission (BLE-01, BLE-02, BLE-03, BLE-04)

**Files:**
- Modify: `native/tauri/src/btleplug_dispatcher.rs`
- Inspect only: `src/ipc/public-manager.ts` (IpcAdapterWatchOwner qualification)
- Test: cargo tests in `native/tauri/src/btleplug_dispatcher.rs`

**BLE-01:** Separate live-operation capacity from 30s replay tombstones. Reserve admission for cleanup/control (`scan.stop`, `gatt.unsubscribe`, `connection.disconnect`). Legitimate exhaustion is backpressure, not `protocol.violation`. Replay of an old correlation must still reject. Keep `MAX_CORRELATIONS` and TTL; change the *coupling*. Existing tests `full_replay_window_rejects_new_work_without_evicting_a_live_tombstone` and `in_flight_plus_completed_correlations_never_exceed_256` currently encode the defect — replace them with tests that prove cleanup still admits after >256 unique completed routes, and that replay still rejects.

**BLE-02:** On late connect after caller/lease gone, create an explicit orphan/pending-connection cleanup owner holding the `Peripheral`, peer id, lease/generation, retry state *before* compensating disconnect. Keep reservation and owner together. Release both only after proven physical release. `release`/`settle_caller` must drive orphan cleanup. Old cleanup result must not release a newer generation's reservation.

**BLE-03:** `fail_scan_stream` must keep the exact scan owner in a stopping state until `stop_scan` completes. Do not clear `scan_owner` before native stop. Do not discard stop with `.ok()`. Serialize new scan admission against outstanding stop. Failed stop remains retryable.

**BLE-04:** After `unsubscribe().await`, re-check lease/generation before mutating caller state. If the old lease is gone, quarantine the resource on the old generation; never insert into the replacement caller. Audit `stop_scan` / `unsubscribe` post-await mutations in the same file and apply the same rule if they reinsert/steal.

### Task 6: Android local registration vs proven link loss (BLE-14)

**Files:**
- Modify: `android/src/main/java/com/sfourdrinier/unifiedblemanager/radio/OwnedAndroidGattRadio.kt`
- Modify tests that currently lock in the defect: `android/src/test/java/com/sfourdrinier/unifiedblemanager/protocol/UnifiedBleProtocolAndroidDispatcherLifecycleTest.kt`
- Inspect: dispatcher `androidGattOperationFailureCode`, JS `nativeOperationFailure`

**Nuance:** 4.0.20–4.0.22 *intentionally* mapped some registration failures to `connection.lost` because Android can reject `setCharacteristicNotification` after the link is gone while `BluetoothManager.getConnectionState` still says connected. Do **not** blindly revert that. Do **not** break 4.0.22 CCCD/disconnect two-signal arbitration.

Required behavior:
- Local `setCharacteristicNotification` false is **not** proven peer-disconnect by itself.
- Generation-matched `onConnectionStateChange(DISCONNECTED)` remains the physical-loss authority.
- If registration fails while the generation-matched connection is still connected and a later read can succeed, the error is a registration failure, not fabricated `connectionLost`.
- Genuine disconnect (status 19 / disconnect callback) still classifies as link loss.
- Preserve rollback failure as a cleanup obligation rather than upgrading it into an unsupported stronger fact when `isCurrentGatt` is true and no disconnect callback arrived.

- [ ] Separate test: genuine disconnect still link loss
- [ ] Update tests that asserted registration failure → `connectionLost` only where that mapping is now wrong
