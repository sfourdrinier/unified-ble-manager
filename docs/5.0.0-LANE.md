# UBM 5.0 lane (`5.0.0`)

## Status

**Historical lane record.** This document records how the isolated `5.0.0`
integration lane was operated. It does not govern the release candidate after
the owner authorized publication. The live release procedure is
[`../RELEASE.md`](../RELEASE.md), and the agent principles remain in
[`../AGENTS.md`](../AGENTS.md).

`5.0.0-rc.3` is not published until npm registry verification succeeds. Its
release path is an integration PR into `main`, then an annotated
`v5.0.0-rc.3` tag on that exact current `main` commit. The tag workflow
publishes with provenance to the npm `next` dist-tag; it must never be
published manually from a workstation or from this historical lane branch.

## Purpose

The `5.0.0` branch is the integration base for UBM 5.0 work
(trackourhealth/bun-mono#1188). All 5.0 worker branches integrate there —
never directly to `main`.

## Branch rules

- Worker branches are named `codex/ubm5-*`.
- Worker branches set their base (and PR target) to `5.0.0`. Never `main`.
- Historical rule: workers never merged the lane, or any lane worker branch,
  into `main` directly.
- Historical rule: workers never created `v*` tags from the lane. Tags remain
  manual and `main`-sourced per [`../RELEASE.md`](../RELEASE.md); a lane tag
  could trigger the publish workflow (see below).
- Current release rule: the approved release PR may integrate the final
  candidate into `main`; only the release owner tags the exact resulting
  `main` commit. The publish workflow, not a worker or workstation, publishes
  the package.

## CI coverage

Since the lane-scoped trigger change in
[`../.github/workflows/ci.yml`](../.github/workflows/ci.yml) (`U0`
CI-coverage slice), the lane gets the normal checks:

- pushes to the `5.0.0` branch run CI, as do pushes to `main` and
  `release/**`;
- pull requests whose base is `5.0.0` run CI, as do PRs targeting `main`,
  `agent/**`, and `release/**`.

Apple compile checks keep their existing gating (path filter on `main`
pushes, `ci:apple` label opt-in on PRs, or manual dispatch); the trigger
change did not widen them.

## Why the lane cannot accidentally publish

`.github/workflows/publish.yml` (read-only reference; this lane must not
modify it) only starts on pushed `v*.*.*` tags, and then requires, before
any initial publication, that the tag name equal the root `package.json`
version and that the tagged commit be exactly the current `main` commit.
The historical lane created no `v*` tags and did not merge to `main`, so a
lane push could not satisfy either admission check. The approved RC now uses
the same safeguards: a release tag must equal the package version and identify
the exact current `main` commit before the OIDC publish job can run.
