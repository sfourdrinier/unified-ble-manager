# npm `next` follows a newer stable release

- Symptom: after 5.1.3, npm `next` still resolved to 5.0.0-rc.21 (2026-10-08),
  so `npm install unified-ble-manager@next` installed a version older than
  `latest`.
- Cause: the policy set `next` only for numbered candidates; a stable publish
  wrote `latest` alone, and npm trusted publishing could not move tags until
  the opt-in "Allow npm dist-tag" permission (GitHub changelog, 2026-09-30;
  npm CLI 11.21.0+).
- Change: `scripts/release/advance-next-dist-tag.js` runs in the publish job
  after provenance verification and before the GitHub Release. For a stable
  version it adds `next` when `next` is absent or semver-older, leaves a newer
  candidate, refuses a `next` it cannot order, and confirms the result by
  reading the registry back (bounded). A refused write fails the job with the
  setting to enable; the recovery rerun skips the published upload. npm pin
  raised to `^11.21.0`.
- Tests: `__tests__/AdvanceNextDistTag.test.js`; `ReleaseRetrySafety` pins the
  step's position; `PackageModernization` pins the npm floor.
- Requires: "Allow npm dist-tag" enabled on the package's trusted publisher
  (npmjs.com, maintainer login). Not verifiable from CI before a stable tag.
- 5.1.3's `next` is not moved by this change (its tag runs its own workflow);
  the next stable release, or a maintainer `npm dist-tag add`, moves it.
