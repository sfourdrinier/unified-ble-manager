# Native notification receipts / 5.1.0 candidate

Optional `NotificationReceipt` preserves paired host UTC/monotonic ingress
clocks and their epoch through bounded mobile/core queues, fan-out, native drains,
NAPI, RN, continuation claims, IPC, Electron and public GATT values. Receipt-free
hosts remain explicit. This is host ingress evidence, not device acquisition time
or a new physical/backend qualification. Existing queue admission, loss reporting
and cleanup ownership remain authoritative.

The root-cause regression reproduced an identical later payload overflowing and
retiming an already retained packet; receipts now attach atomically at admission.
Invalid receipt evidence is rejected before admission. Signed fractional UTC is
preserved. TypeScript and Rust reject whitespace-only clock identities alike.

One independent release review identified missing public named-type exports and
clock-ID validation drift. Both were confirmed and fixed. The wire regression
failed before the guard correction and passed after it; the exported type is
included in generated public API reports.

Prior validation: core 195 tests; mobile native ingress/fan-out tests on both
scripted host paths; five public/native/desktop/Electron/backlog suites 473 tests.
Release fixes and identity checks passed 274 tests. Package/prepack, lint,
typecheck, generated documentation and native artifact freshness passed before
release metadata preparation. The candidate includes the previously committed
H10 driver capture fixes; simulator evidence does not establish physical fidelity.

5.1.0 is an additive minor API release. Package/backend/TCK/Tauri identities,
consumer docs, generated API/support docs, dependency artifacts and the example
Tauri lockfile are aligned. Publication must use the existing tag-driven trusted
publisher from current main after clean qualification and hosted checks. No npm
publish from this checkout. Final gate and publication receipts are recorded by
the linked PR/release; unverified physical scenarios remain unverified.

Clean-checkout integration caught three additional gaps before publication:
Tauri's new receipt-bearing notification variant was not handled; retirement
of a consumer stripped a final buffered receipt; and recording replay compared
JavaScript JSON float formatting with native persisted byte counts. Tauri now
serializes the receipt, retirement drains paired evidence, and the native prepare
path validates exact original JSON row spans before decoding. Synthetic decoding
retains its strict independent byte check. The raw fixture bridge no longer
parses/reserializes native responses; malformed size claims remain rejected.

A native storage regression also reproduced Serde decoding a UTC timestamp one
ULP away from its stored value (1760662567890.0015). The desktop owner's Serde
JSON dependency enables float_roundtrip, shared transitively by mobile and
Tauri/NAPI consumers, without a dependency version change. Native artifacts are
refreshed after this source change. Receipt-free tails remain unchanged. The
regressions cover fractional/signed timestamps, final retirement tails, Unicode,
quoted JSON-looking metadata, duplicate envelope fields, invalid receipts,
immutability, byte caps, and repeated retained-prefix replay. Final validation
must still run on the committed candidate and hosted cross-platform lanes.

Hosted CI exposed receipt-free byte-size assumptions in two native tests and
nondeterministic receipt clocks in Rust-generated golden vectors. The loss tests
now observe the same ingress through an independent subscriber, compare retained
receipt identity, and assert exact refused-body byte totals including each actual
receipt. The cutoff fence observes the target session's wake rather than the new
audit subscriber's wake. No loss assertion was relaxed. Golden generation checks
receipt validity before normalizing only dynamic clock evidence; TypeScript also
asserts the normalized receipt structure. The affected native targets passed 119
tests, golden generation and a separate stability run passed, and the TypeScript
golden suite passed 68 tests after an observed failing receipt regression.

The first hosted Classic Android failure was a Gradle distribution download read
timeout before JVM compilation/tests, rather than an application failure. No CI,
toolchain or network-policy changes were made for it. Final workspace and
cross-platform gates must pass on the updated candidate before publication.

The canonical native identity checker and `pnpm native:status --only
apple,android,desktop` verified all locally applicable artifacts remain fresh
because the final corrections touch tests only. Existing binaries and their
source digests are reused rather than rebuilt unnecessarily. Full-workspace
`cargo clippy --locked --all-targets -- -D warnings` passed on the correction tree.
