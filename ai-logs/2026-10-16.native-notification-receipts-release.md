# Native notification receipts / 5.1.0 candidate

Optional `NotificationReceipt` preserves paired host UTC/monotonic ingress
clocks and their epoch through bounded mobile/core queues, fan-out, native drains,
NAPI, RN, continuation claims, IPC, Electron and public GATT values. Receipt-free
hosts remain explicit. This is host ingress evidence, not device acquisition time
or a new physical/backend qualification. Existing queue admission, loss reporting
and cleanup ownership remain authoritative.

The root-cause regression reproduced an identical later payload overflowing and
retiming an already retained packet; receipts now attach atomically at admission.
Invalid receipt evidence is rejected before admission. Signed fractional UTC is
preserved. TypeScript and Rust reject whitespace-only clock identities alike.

One independent release review identified missing public named-type exports and
clock-ID validation drift. Both were confirmed and fixed. The wire regression
failed before the guard correction and passed after it; the exported type is
included in generated public API reports.

Prior validation: core 195 tests; mobile native ingress/fan-out tests on both
scripted host paths; five public/native/desktop/Electron/backlog suites 473 tests.
Release fixes and identity checks passed 274 tests. Package/prepack, lint,
typecheck, generated documentation and native artifact freshness passed before
release metadata preparation. The candidate includes the previously committed
H10 driver capture fixes; simulator evidence does not establish physical fidelity.

5.1.0 is an additive minor API release. Package/backend/TCK/Tauri identities,
consumer docs, generated API/support docs, dependency artifacts and the example
Tauri lockfile are aligned. Publication must use the existing tag-driven trusted
publisher from current main after clean qualification and hosted checks. No npm
publish from this checkout. Final gate and publication receipts are recorded by
the linked PR/release; unverified physical scenarios remain unverified.
